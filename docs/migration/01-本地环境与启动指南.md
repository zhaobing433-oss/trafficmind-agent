# TrafficMind Agent 本地环境与启动指南

> 用途：半年以后拿一台新 Windows 电脑，10 分钟内恢复 TrafficMind 开发环境。
> 本文命令统一从仓库根目录运行，不依赖旧电脑的用户名 / 绝对路径 / 全局配置。

---

## 1. 推荐开发拓扑

```
Browser  (http://localhost:5173)
    │  /api/*（Vite rewrite 去掉 /api 前缀）
    ▼
Vite dev proxy  (frontend)
    │
    ▼
Backend  (127.0.0.1:8000)   ← 只运行 1 个
    │
    ├── SQLite   backend/data/trafficmind.db   （自动创建）
    └── Chroma   backend/data/vector_db         （自动创建/重建）
```

- 只运行 **1 个 frontend + 1 个 backend**。
- 不要双 backend（8000/8001），不要多个 Vite 实例——这是旧电脑踩过的坑。

## 5. Backend 环境

从**仓库根目录**执行（不要 `cd backend` 后再用 `backend.app:app`，避免 import 路径混乱）：

```powershell
python -m venv backend\.venv
backend\.venv\Scripts\python.exe -m pip install --upgrade pip
backend\.venv\Scripts\python.exe -m pip install -r backend\requirements.txt
```

> 依赖清单以 `backend/requirements.txt` 为准（已 pin 版本）。
> **不要复制旧 venv**，新电脑必须重建。

---

## 6. 环境变量

模板已随源码提供：`backend/.env.example`。在**仓库根目录**创建 `.env`（或 `backend/.env`，二者均可，根目录优先）：

```powershell
copy backend\.env.example .env
```

然后编辑 `.env`（示例，**Secret 绝不用真实值占位**）：

```ini
# DeepSeek（可选：不配则 LLM 降级，确定性核心仍可运行）
DEEPSEEK_API_KEY=<SET_MANUALLY>
DEEPSEEK_BASE_URL=https://api.deepseek.com
DEEPSEEK_MODEL=deepseek-chat

# RAG V2（可选）
RAG_ALLOW_MODEL_DOWNLOAD=true
```

变量一览（只记名称与用途，不记真实值）：

| 变量名 | 用途 | 必需 | Secret |
|---|---|---|---|
| `DEEPSEEK_API_KEY` | LLM 调用 | LLM 必需 | ✅ |
| `DEEPSEEK_BASE_URL` | 接口地址 | 可选 | 否 |
| `DEEPSEEK_MODEL` | 模型名 | 可选 | 否 |
| `RAG_ALLOW_MODEL_DOWNLOAD` | 是否下载本地 embedding 模型 | 可选 | 否 |

> 无 Key 时：风险评分 / 规则匹配 / 状态流转 / DAG 编排 / 仲裁等**确定性功能照常**，
> 仅 LLM 润色 / 融合 / 规划 Proposal 降级为模板。

## 7. Backend 启动

仓库根目录：

```powershell
backend\.venv\Scripts\python.exe -m uvicorn backend.app:app --host 127.0.0.1 --port 8000
```

验证：

```powershell
# 健康检查
Invoke-RestMethod http://127.0.0.1:8000/health
# 规划接口（Plan Center 数据源）
Invoke-RestMethod http://127.0.0.1:8000/planning/plans
```

## 9. Proxy

推荐：**不创建 `frontend/.env.local`**，直接使用 `vite.config.ts` 默认值 `http://localhost:8000`。

若确实需要显式指定：

```ini
# frontend/.env.local（非 Secret）
VITE_PROXY_TARGET=http://localhost:8000
```

> 旧电脑曾因 `.env.local` 指向 `:8001` 的 stale backend 导致 Plan Center 空。
> 新电脑统一指向 `:8000`。

---

## 10. Database

- `backend/data/trafficmind.db` 由启动流程**自动创建**（`lifespan` 幂等初始化）。
- **不复制 DB 也能 clean start**。
- 复制旧 DB 的目的是保留开发历史，不是启动必需。
- 若迁移旧 DB：**必须在 backend 停止时复制**，复制后重启 backend，历史记录可读。

---

## 11. RAG / Chroma

- Chroma（`backend/data/vector_db`）与 RAG 索引（`backend/data/rag_v2`）**自动创建/重建**。
- 首次运行若启用模型下载（`RAG_ALLOW_MODEL_DOWNLOAD=true`），会从 HuggingFace 下载 Qwen3 Embedding/Reranker 模型，**可能较慢**。
- 也可设置 `RAG_ALLOW_MODEL_DOWNLOAD=false` 走 hash 降级路径，无需下载。
- **Windows Chroma lock**：Chroma 在 Windows 持有文件锁，复制/删除 `vector_db` 前必须先停止 backend。

## 12. 常见问题

### A. Plan Center 显示"暂无计划"，但后端有 Plan

依次排查：

1. `GET http://127.0.0.1:8000/planning/plans` 是否有数据
2. `GET http://localhost:5173/api/planning/plans` 是否与第 1 步一致
3. 若两者不同：检查 `VITE_PROXY_TARGET` 是否指向了另一个（stale）backend 端口

### B. 端口占用

```powershell
Get-NetTCPConnection -LocalPort 8000 -State Listen -ErrorAction SilentlyContinue
# 或
netstat -ano | findstr :8000
```

### C. 多个 backend

只保留 `:8000` 一个 backend。若同时存在 8001 等旧进程，会因代码版本不同导致接口行为不一致。

### D. Chroma lock

操作 `backend/data/vector_db` 前先停止 backend，否则文件被锁。

### E. LLM unavailable

`/health` 中 `llmAvailable=false` 表示未检测到 Key。检查 `DEEPSEEK_API_KEY` 是否正确配置；这不阻塞确定性核心功能。
